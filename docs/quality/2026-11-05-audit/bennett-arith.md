# bennett-arith quality audit 2026-11-05

HEAD 6764ad2. All timings in a `git archive` copy of HEAD (repo untouched; only `.tmp/audit-tmp` created and an `.tmp` listing read). Gate (`scripts/gate`, `scripts/pre-push`, ~8 h) never run.

## Verdict
- Code: C- . Circuit generators (Python) are tidy; the soft-float C (`trans.h`, `core.c`) is dense, long &&/|| chains, jam-and-hope approximations with three open P0s at HEAD (ufr, 8eb, rn8 reproduce).
- Tests: C+ . Arithmetic and circuit tests are genuinely oracle-backed (independent Fraction/MPFR/simulator/reference interpreter), but every transcendental rounding test accepts 1-4 ulp, so it cannot see a wrong rounding side; the repair tests are one-point regressions per found bug.
- Build: B . Reproducible byte-for-byte, 54-85 s per LLVM major; but the full gate is ~8 h and a part of the suite is not in it.

## Test quality
### The tolerance question (answers the P0 ufr/8eb brief)
Every transcendental assertion that compares a number compares by ulp tolerance:

| Site | Tolerance | Mode(s) | Checks | Can it see wrong side (1 ulp wrong)? |
|---|---|---|---|---|
| `tests/test_trans.py:78` | <= 4 ulp (MPFR 384-bit) | default (nearest, non-`_rm` entry) | 130,464 per major | No. Observed max 0.5000 ulp: a bound of 0.5 + eps would pass and catch |
| `tests/test_trans_boundaries.py:23` | <= 4 ulp | all 5 (exp/exp2/exp10 only) | 14,655 | No (wrong side is 1 ulp) |
| `tests/test_trans_extra.py:35` | <= 1 ulp, exhaustive f16/bf16 sin | nearest | 131,072 inputs | No (1 ulp allowed, nearest wrong choice is exactly 1 ulp) |
| `tests/test_trans_extra.py:52` | <= 4 ulp (ppcf128) | nearest | hundreds | No |
| `tests/test_trans_extra.py:66` | <= 4 ulp, one point x=1/2 | all 5 | ~600 | No; also one point only, with rm0..4 giving results within 1 ulp of each other |
| `tests/test_trans_extra.py:78` | rel 2^-(p-2) (about 2 ulp) | nearest | few | No |
| `softfloat/generate.py` manifest | claims "deterministic approximation; no global correct-rounding or ulp-bound proof" | | | the contract itself does not promise it |

So 6 tolerance sites, about 280k assertions per major, 0 of which can detect a wrong rounding side; I count no transcendental `_rm` test outside the targeted exact ones below.
Exact (bit-for-bit) transcendental checks exist only for: exp-family limit, tanh>=256, exact dyadic pow/exp10/log10/sincospi (`test_review_numeric.py:44-109`), ppc exp |x|<=2^-112 (`test_ppc_exp.py`), special values (`test_trans_extra.py` end). They are one-bug-one-regression-test, made after the review found each bug.
Demonstration at HEAD (probe in the scratch copy, tests above all green): `tanh_f64_rm(100.0, rm=1/3)` returns `0x3ff0000000000000` instead of `0x3fefffffffffffff`; `tan_f64_rm(2^-169, up)` returns x itself. Both reproduce, so ufr and 8eb are unfixed at HEAD and the 130k green checks do not flag them.

### Oracle vs self-reference
- `tests/test_edge.py`: docstring "No host FP, libm, APFloat, or implementation sources"; expected values from its own Fraction encoder/`roundedq` (independent re-implementation of IEEE, not the library). Oracle-backed, but a single shared `encode`/`decode`/`roundedq` serves as every oracle (a bug there would be a systematic blind spot; partial cross-check by APFloat in `test_ppc.py`).
- Transcendentals: MPFR via ctypes (independent, 384-bit and 2048-bit), but see tolerances. PPC: APFloat (C++ `APFloat18/23.cpp`, untracked in `.tmp`; `tests/ppc_oracle.cpp` tracked) with 0.2.12 overrides noted (`test_ppc.py:66`); `ppc_exact_oracle.py` is Fractions.
- Circuits: independent bit-sliced simulator in `harness.py` (reads emitted text, does not import a generator), plus the sibling reference interpreter as differential oracle, plus a mutation test.
- Not independent: cost tests assert closed formulas written next to the generator; `test_reproduces_byte_for_byte` is snapshot determinism.

## Code quality
Findings against rule 9 / fail-fast:
- `softfloat/trans.h:246-256` (`exact` flag chain): 10 `&&/||` clauses keyed on `op==`, then patched with five following `if(...)exact=1;` lines; this is the "flags where a state enum belongs / long chain" pattern and is why l95 happened (spurious inexact). Cost: each new op needs edits in 3 places.
- `trans.h:222-244` single function does unpack, domain, dispatch, flags, pack, with `return` in the middle at 205-218 (tanh special branch bypassing normal flags). Complexity hotspot; C functions are ~100 lines of semicolon-joined statements (one-line for loops at 237-240).
- `trans.h` jammed independent 224-bit quotients: `tan = s/c`, `asin = atan2(x, sqrt(...))`, tanh series (`:221-240`) are error-prone by construction; rounding side is wrong when the error is smaller than the jam bit. Root cause of 8eb/ufr, per review.
- `softfloat/core.c:23,149`: `if(!x)return 0;`, `if(a.kind==NANV){*flags|=1;return 0;}` flagged sentinel returns (reviewed: set flags first, so acceptable, but silent zero). `core.c:95` `pack()` tininess reads the accumulated flags word (review nit).
- `adders/constructions.py:573` `mulmod_const`: does not validate k < m, product width 2W silently wraps (rn8). Silent wrong result instead of assert. `_check_modulus` exists, no `_check_multiplier`.
- `adders/generate.py:110` `one` CLI: `int(w,0)` / tuple parsing, `TypeError` on single-word table (rhn).
- Tracked WIP litter: `tests/__pycache__/ppc_exact_oracle.cpython-312.pyc` is tracked (1 file, modified in the working tree; an untracked second .pyc). Source files also carry `sys.dont_write_bytecode=True`, yet bytecode was committed.
- Bead refs in source: `softfloat/generate.py:325` (`bead='bennett-arith-wvh.1'`, manifest data), plus the two schema strings; light, around 3 occurrences, acceptable. 21 of 52 commit subjects are non-descriptive `wip(codex job ...)`.

## What is good
1. Byte-for-byte reproducible publication: both majors rebuild identical to tracked dist in about 1-1.5 min, hashed in `SHA256SUMS`/manifest (verified by me, all 6 files cmp).
2. Circuit harness is independent of the generators and includes a mutation test (`test_adders.py:439`); exhaustive small-width coverage with rejection of invalid parameters.
3. Basic float ops use a pure-Fraction oracle with bit-exact value and flag checks in all 5 rounding modes (`test_edge.py`), plus APFloat cross-checks for PPC.
4. The 2026-11-03 review process found real bugs with concrete reproductions, and the fixes came with MPFR interval tests (`test_review_numeric.py`).
5. Observed accuracy is actually correct rounding in nearest mode (max 0.5000 ulp over 130k checks), so tightening is cheap.

## Recommendations
1. Replace the 4-ulp and 1-ulp bounds in `test_trans.py:78`, `test_trans_boundaries.py:23`, `test_trans_extra.py:35/52/66` with exact comparison against the MPFR-bracket correct rounding (skip only inconclusive brackets, as the cross-check probes did): catches ufr, 8eb now; costs one function.
2. Add a directed-mode sweep (5 modes x all `_rm` ops x tiny/large/near-1 x) to `test_trans.py`; today `_rm` is checked at x=1/2 only.
3. Fix rn8 (`mulmod_const` must reject or reduce k >= m) and add a k>=m case to `test_adders.py:262`.
4. Wire `softfloat/test_*.py` into `scripts/gate` (they are unreferenced) or delete.
5. Untrack `tests/__pycache__` and add it to `.gitignore`.
6. Restructure the `exact`-flag chain in `trans.h:246-256` into a per-op table; split `trans_eval` into domain, core, pack stages.
7. Run the circuits suite against the gate-pinned `bennett-isa-ref` (ecaaac0) to confirm the 3 K91 failures are drift; if so re-pin or fix the objects for token_aliases.
