- **[codex] B2** (Recommended exact spec diff, §8.3 kind/channel admission; interactions with §§4.4 and 12.3; contract): The diff admits kind=channel with CPTP normalization but leaves epsilon as the existing accuracy obligation. §4.4 defines that obligation for a realised unitary in operator norm; a general channel has no such unitary. §12.3 additionally requires a numerical claim for a controlled unitary variant. ## sol

The defect, phase witness and hash analysis are sound. One contract contradiction prevents applying the diff verbatim: expression syntax is treated as requiring a model even when epsilon is exactly zero, while the same diff permits exact entries to omit it.

**Path to accept:** Replace the conflicting expression-valued and exact-entry rules with B1’s value-based rule, including the stated outcomes for identically-zero and mixed-control epsilon expressions. No source or reference-catalog change is required.

- **C1 5**: The proposal adds target realisation data without changing the tiers, state or step machine of §3. *Change:* In §8.3, add: “Realisation models describe target implementations; they do not replace the reference semantics of §3–§7.”
- **C2 5**: The §4.4 matrices and phase-sensitive exact-gate obligations remain intact. No opcode or reference-catalog recipe changes. *Change:* Replace the angle-binding sentence with: “theta denotes the exact real value represented by the finite binary64 angle of §3.1 and §11.1 K20, without decimal re-rounding.”
- **C3 4**: The X/−X witness is correct. Exact rational matrix checks confirm equal uncontrolled channels and controlled Bell coherences +1/2 versus −1/2. The requirement for implementation-specific channel control data agrees with [Abbott et al.](https://arxiv.org/abs/1810.09826). *Change:* In §8.3, add: “A numerical claim requires a phase-fixed unitary model; a channel description alone cannot discharge an operator-norm claim. These model encodings do not waive §4.4 conformance.”
- **C4 4**: Binding models to target_hash repairs the missing native-operation identity. Explicitly connecting model instantiation to requested accuracy would clarify expression-valued native families. *Change:* In §8.3, add: “Model expressions bind k, c and eps to the same resolved values used for the matched entry’s §8.1 error and cost evaluation; angle parameters retain their exact binary64 values.”
- **C5 4**: The missing-model defect is real: §8.3 supplies no realised operator while §12.1 requires its reconstruction. Hash migration is correctly described, but the proposed model-presence rules conflict for exact expression-valued epsilon (B1). *Change:* Replace the syntactic expression-valued requirement with B1’s value-based model requirement and explicit zero-epsilon convention.
- **C6 5**: The proposal states normalization, phase, control and rigorous distance obligations without treating interval boxes as operations. The verification-index script passes; the catalog check confirms the published 219-recipe hash. No native-model checker execution is claimed. *Change:* In §15 suite D, add: “For controlled X and controlled −X, a numerical bound-zero claim against controlled X passes only for the former; their uncontrolled channels are equal.”
- **C7 5**: Independent phase-sensitive and channel verification implements North Star §5.1 part 2. Approximate algorithms remain supported, and physical failure probabilities remain distinct from logical approximation error. The cited defect clauses are correctly identified. *Change:* In the migration paragraph, add: “Missing-model reporting qualifies independent validation; it does not change the program’s reference semantics or remove approximate algorithms from scope.”
- **C8 4**: The mechanism and legacy behavior are understandable. B1 needs correction; the concrete model-format version and representative serialized bytes remain publication work. *Change:* In §8.3, name the initial model format, for example “bennett.native-model/1”, and publish a canonical X model illustrating every mandatory field; unsupported versions retain the stated unsupported-model outcome.

Suggestions:
1. In §8.3, state: “A channel-only model supports channel comparison; an operator-norm claim requires a phase-fixed realised unitary. Model normalization does not itself establish §4.4 accuracy or an inverse.” For example, Ch(X)=Ch(−X) cannot establish numerical bound zero against X. Retaining the existing §4.4 obligations is preferable for this K repair; admitting general nonunitary native gates would instead require an explicit amendment defining their accuracy and reversal semantics.
2. In §8.3, state: “Model instantiation uses the matched entry’s resolved k, c, eps and angle values. An explicit operand-to-wire map converts the model basis to §12.1’s controls-first allocation basis.” This makes the existing reconstruction obligation concrete for accuracy-dependent models and avoids confusing §8.3’s template control order with the certificate matrix order.
3. For the initial versioned model schema, publish canonical positive and negative examples. Include exact X without a model, X and −X models under one outer control, and a malformed Kraus list. Expected results: equal uncontrolled channels, opposite controlled Bell off-diagonal entries ±1/2, rejection of the −X bound-zero numerical claim, and rejection of a non-trace-preserving model.

## codex

The missing native-operator model is a real defect, and the phase witness and hash analysis are sound. Two contract-rule conflicts prevent applying this exact diff. The accepted core semantics need no revision.

**Path to accept:** 1. Resolve the zero-valued-expression contradiction using B1. 2. Decide native channel admissibility and its error metric using B2; the unitary-equivalent representation rule is the smallest repair compatible with current §4.4. No source or reference-catalog change is needed for that authorized 0.9 K repair.

- **C1 5**: The proposal leaves §§3.1–3.7 state, tiers and execution rules unchanged. *Change:* No machine-model change required.
- **C2 4**: §4.4 defines native gate conformance through phase-sensitive unitary operator distance. The proposed channel models are not reconciled with that rule. *Change:* In §8.3 state: “Native models must satisfy §4.4’s unitary conformance obligation; a channel-form representation must additionally identify the phase-bearing unitary it represents.” See B2.
- **C3 4**: The X/−X witness is correct: uncontrolled channels coincide, while their controlled outputs are orthogonal. Requiring additional control information for channels agrees with [Abbott et al.](https://quantum-journal.org/papers/q-2020-09-24-333/). The unresolved channel/epsilon interaction remains material. *Change:* In §8.3 state: “For every resolved control context, the model binds the phase-bearing logical unitary used by numerical verification; a Kraus representation alone cannot supply this phase.”
- **C4 3**: The target extension supplies the missing operation identity, but its expression-valued-epsilon requirement conflicts with its exact-entry exemption, and channel epsilon has no decided interpretation. *Change:* Replace §8.3’s syntactic model requirement with the evaluated-epsilon rule in B1 and specify the model admissibility/error rule in B2.
- **C5 3**: The defect is genuine under §§8.3 and 12.1. Target-hash and dependent schedule/certificate invalidation are correctly identified. Unchanged source and catalog identities are consistent with an authorized in-version K repair. *Change:* In §8.3 state: “A zero-valued epsilon expression retains the exact-opcode convention; a positive evaluated epsilon requires a model for independent verification, with missing legacy models reported as unchecked.”
- **C6 4**: The published verification script passed, including Bell-state orthogonality. It does not execute a native-model checker, as the note correctly discloses. §12.1 supplies numerical and channel procedures, but neither resolves the new native-channel admission question. *Change:* In the conformance vectors state: “For controlled X versus controlled −X, operator distance is 2, while §12.1’s Frobenius upper bound is 2√2; a numerical claim with bound 2 therefore rejects and bound 3 can pass at sufficient precision.”
- **C7 5**: Independent approximation verification implements North Star §§4.4 and 5.1. The proposal supplies a mechanism for approximate algorithms and does not substitute unchecked legacy handling for that mechanism. *Change:* No scope change required.
- **C8 4**: The repair is focused and distinguishes model identity from advertised accuracy. Concrete model encoding and context mapping need publication, but those mechanics are not independently blocking once the semantic conflicts are repaired. *Change:* In §8.3 state: “Resolve the model using the matched entry’s exact invocation context and explicitly map its ordered operand bits to §12.1’s controls-first allocation basis.”

Suggestions:
1. §8.3 parameter binding: cite §§3.1 and 11.1 K20 for angle representation, rather than relying on §4.4 alone. State: “A theta parameter is the exact real represented by its finite binary64 binding; model evaluation preserves that binding.” For source angle 0.1, the value is 3602879701896397/36028797018963968, not 1/10.
2. Conformance vectors: distinguish mathematical distances from checker acceptance. State: “Controlled X and controlled −X have operator distance 2 and channel diamond distance 2. The numerical procedure obtains Frobenius bound 2√2 for the latter comparison.” Also retain §12.1’s existing rule that a zero-distance channel does not make a zero-bound, non-strict SDP witness pass.
3. Hashes and release: state explicitly, “Unchanged source identities assume this repair retains the ISA 0.9 semantic envelope. A full ISA-version bump requires regenerating the §9.2 identities. Installing changed model bytes requires regenerating target_hash, dependent schedule_hash values and certificates.” The reference-catalog check passed with the published 219-recipe hash.
