## Blocking issues

- **[sol] FR-1** (Recommended exact spec diff, §12.3; interaction with §§5.3 and 14.1; contract): §12.3 requires verification.fault_rate in every region record, including action and perm_action. The diff unconditionally requires counts to be recomputed from F_B and applies its scheduled-context requirements to a 'scheduled region'. But §5.3 explicitly gives actions no fault outcome, and §14.1 defines F_B only for an oracle's reference body. Consequently the mandatory calculation is undefined for an otherwise valid action certificate. The published conformance/fixtures/controlled-action-09/controlled.bisa supplies a concrete witness: both controlled and flip are perm_action regions, neither invokes an oracle, and their invocation budget is zero. Filling in the proposed invocation fields does not create an F_B for either action. A checker must invent an exemption or fail to discharge a valid action certificate. *Fix:* In §12.3, change the schema to fault_rate: null | {invocation,domain,faults_by_code,undefined_excluded,layout_dependent_excluded}. State: 'The fault-rate recount and context requirements apply only to oracle records. For action and perm_action records, verification.fault_rate MUST be null and fault_rate_contexts MUST be absent. Actions have no fault outcome of their own (§5.3); each contained lifted-oracle invocation remains subject to the recount requirements in its corresponding oracle region record.' For the controlled-X fixture, both action records therefore contain fault_rate:null and no fault_rate_contexts. Alternatively retain action-shaped records, explicitly exempt them from F_B evaluation, and require faults_by_code:{} and both exclusion counts zero; I prefer null because it distinguishes inapplicability from a verified zero-fault oracle recount.
- **[codex] CFR-1** (Recommended exact spec diff: §12.3 fault_rate applicability; contract): *Fix:* In §12.3, make the field 'fault_rate: <oracle recount record> | null' and state: 'F_B recounts and fault_rate_contexts apply only to regions of kind oracle. For action and perm_action, fault_rate MUST be null and fault_rate_contexts MUST be absent. This denotes no action-owned fault outcome; it does not assert that nested oracle invocations are fault-free. Nested oracle recounts retain their own invocation/context bindings.' The corrected controlled-action fixture has fault_rate:null on both perm_action records. Alternatively, retain an explicitly defined empty action placeholder that is never evaluated through F_B and never discharges a callee obligation; I recommend null because it distinguishes inapplicability from a verified zero-fault recount.

The proposed 'enumerated applicable domain count' also leaves unclear whether excluded tuples remain in the F_B recount. North Star §5.1 excludes these inputs from native comparison while retaining reference validation. ## sol

The invocation defect is real, the 256-tuple witness is correct, and the hash/catalog claims hold for the proposed in-version repair. One contract blocker remains: the unconditional recount rule invokes oracle-only F_B semantics for required action records.

**Path to accept:** Scope F_B recounts and their context requirements to oracle records, and define the required action field explicitly using the null rule in FR-1 or its stated empty-record alternative. No core semantic change is needed.

- **C1 5**: The proposal changes certificate metadata, leaving the accepted machine state and step relation unchanged. *Change:* None required in §§3–5; retain the existing machine model.
- **C2 5**: §4.2 charges one step per lifted row, and §14.1 makes retval terminate successfully. The two-row witness therefore faults at B=1 and succeeds at B=2. *Change:* §15, optional fixture rule: 'The add/retval oracle with a=1 reports 256 code-1 faults at B=1 and no faults at B=2 over the full eight-bit interface domain.'
- **C3 5**: Counting code(F_B), rather than the accumulated fault word, correctly follows §5.2. Incoming fault word 1 becomes 0 on code-1 failure and remains 1 on success. *Change:* §12.3, optional explicit predicate: 'A domain tuple contributes to faults_by_code[c] exactly when code(F_B(x))=c and c≠0.'
- **C4 5**: Explicit budgets and resolved context bindings preserve §5.4 token semantics without changing target matching or resource accounting. *Change:* None required in §5.4; retain the rule that each oracle invocation uses its supplied token's tuple.
- **C5 4**: The defect is real: §12.3 binds individual claims and scheduled roots but does not bind fault_rate. The proposed repair selects oracle invocations deterministically. Its universal F_B recount requirement, however, also reaches required action records, for which F_B is undefined. *Change:* §12.3: 'Fault-rate recount and context requirements apply only to oracle records. For action and perm_action records, verification.fault_rate MUST be null and fault_rate_contexts MUST be absent.' Update the schema accordingly.
- **C6 4**: The oracle vectors are correct. The verification-index script passes; independent replay using the available ISA-0.8 binary confirms the unchanged arithmetic and boundary semantics. This does not establish complete 0.9 recount implementation. An action applicability vector is missing. *Change:* §15: 'The controlled-X action fixture has fault_rate:null without evaluating F_B; any contained oracle invocations retain independently checked fault-rate records.'
- **C7 4**: The repair preserves North Star §5.1 reporting and §8 zero-fault gates for exact oracle invocations. The blanket recount wording needs qualification to preserve certificates for the quantum actions promised by North Star §4.2. *Change:* §12.3: 'An action's lack of its own fault outcome does not discharge fault-rate obligations for its lifted-oracle callees.'
- **C8 4**: K13 encodings, canonical context order, first-context projection and rejection of unbound verified counts give implementers a practical migration rule. §9.2 confirms that certificate changes leave object_hash, symbol envelopes and schedule_hash unchanged; the published 219-recipe catalog check also passes. *Change:* §12.3: 'For action and perm_action records, null denotes that no action-level fault outcome exists; it is distinct from an oracle recount reporting zero faults.'

Suggestions:
1. §12.3: explicitly state, 'Fault-rate domains use §12.2 component resolution, validity, omission-at-zero and enumeration rules; each enumerated interface tuple contributes separately.' Thus the worked full domain contains 256 tuples, rather than only four distinct oracle inputs.
2. §12.3: state, 'If host limits prevent completion of a legal recount, report unchecked (host limit), discharging no verified fault-rate obligation; do not reject the domain or substitute smaller counts.' This extends §12.2's existing host-limit treatment directly to the new recount operation.
3. In the supporting exclusion wording, identify North Star §§3.2 and 5.1 as the inherited obligation: §12.3 itself presently only declares the exclusion counters. Suggested sentence: 'Exclusion counts require independently validated classifications under the recorded materialisation and classification configuration; unavailable validation leaves the recount unchecked and cannot justify an assumed exclusion.'

## codex

The central defect, clause references, two-budget witness and unchanged non-certificate hash claims check out. The proposal needs two contract corrections: action applicability and its unsupported assumption about exclusion validation. No core semantic change is needed.

**Path to accept:** 1. Restrict F_B recounts to oracles and define an explicit non-applicable representation for actions. 2. Remove the false assertion of existing exclusion validation; define full-domain reference counting and either add the independent classification obligation/default or explicitly identify that dependent contract as unresolved. Preserve the proposed invocation bindings, canonical context projection and migration rule.

- **C1 5**: The proposal leaves the machine state and step relation unchanged. Its budget-sensitive witness agrees with §§3.6, 5.2 and 14.1. *Change:* No change required; retain §14.1's rule that the step counter counts executed rows.
- **C2 5**: §4.2 charges one step each for lift.add and lift.retval. Consequently, B=1 faults and B=2 succeeds for the stated two-row body. *Change:* No instruction change required; retain §4.2's one-step-per-row rule.
- **C3 5**: Counting code(F_B), rather than the final XOR-accumulated fault register, correctly preserves §5.2 semantics. Both incoming-fault-word examples are correct. *Change:* Retain the proposed §12.3 sentence: 'A nonzero incoming fault-register word is not a fault event.'
- **C4 5**: No resource or target semantics change. Under an authorized in-version K repair, §9.2 excludes certificate metadata from object_hash and symbol envelopes; schedule, target and catalog bytes remain unchanged. The catalog check reproduced hash 5de4e4995350313e50217880ba1b95de39cd043283b726337d4894efb005d197. *Change:* No resource change required; retain the note's certificate-byte migration requirement and unchanged object, closure, target, schedule and catalog bindings.
- **C5 3**: The invocation-binding defect is real: §12.3 binds standalone claims individually but supplies no corresponding fault_rate binding. Explicit invocations and canonical context projections repair that defect. However, the new universal recount rule has no action interpretation, and the asserted existing exclusion-validation contract is absent. *Change:* In §12.3, state: 'F_B recount records apply only to oracle regions; action and perm_action records use fault_rate:null and omit fault_rate_contexts.' Also replace the unsupported exclusion-validation premise as specified in CFR-2.
- **C6 4**: The verification script passes. Independent execution of the four x values under both budgets reproduced the stated F_B results; step-check also passed. The 256 count correctly includes all target and fault values. The note accurately discloses that the proposed certificate recount was not executed. *Change:* In §15, add: 'The two-row oracle with args=["1"] has faults_by_code={"1":"256"} at budget=["1","0","0","0"] and {} at budget=["2","0","0","0"]; reordering claims leaves either bound recount unchanged.'
- **C7 4**: Binding zero-fault acceptance to the actual invocation supports North Star §§5.1 and 8. The wording must preserve certificates for actions, which North Star §4.2 and ISA §5.3 distinguish from fallible oracles. *Change:* In §12.3, state: 'An action's absence of its own fault outcome does not discharge a nested oracle's fault-rate obligation; nested oracles are reported separately.'
- **C8 4**: Reusing K13 encodings and §12.1 context keys is clear and economical. The deterministic first-context projection makes migration actionable. Applicability and exclusion accounting still need the two corrections below. *Change:* In the §12.3 context paragraph, replace 'scheduled region reached' with 'oracle region present in the complete §12.1 invocation tree, including default-covered contexts'.

Suggestions:
1. In §12.3, clarify the intrinsic meaning of a contextual rate: 'A fault-rate domain is the underlying oracle's §5.2 domain. Inherited controls do not add domain components or suppress intrinsic code(F_B) counts. These counts are not probabilities of reaching the call from the root.' Thus placing the B=1 witness behind a disabled control does not turn its intrinsic 256 failures into zero.
2. In §12.3, replace 'reached' with 'present in the complete §12.1 invocation tree, including default-covered and predicated-off invocations'. For an action containing two calls to the same oracle, both contexts require records even when only one has explicit schedule entries.
3. In §15, add certificate-level acceptance vectors stating: 'Missing invocation, mismatched context invocation, duplicate or omitted context records, and an inconsistent legacy projection reject; equal token tuples with different process-local ids produce the same recount.' Keep the existing disclosure that arithmetic verification alone does not execute these certificate checks.
