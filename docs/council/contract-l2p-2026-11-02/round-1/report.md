## Blocking issues

- **[sol] B1** (Recommended exact spec diff: §§6.2, 6.4 and 11/K65–K81; core): The closed-window exception does not reconcile the remaining source rules with its proposed realisation. §6.2 still requires each cleanup’s external input versions to be current. §11/K81 forms source pairs using §§5.3 and 6.2 before selecting realisations, and §11 retains source dependency ordering. The new text permits closed windows but neither identifies a legal earlier source cleanup as the reference nor expressly permits its relocation across those dependencies. This problem exists even without the optional clean-isometry extension: d=qcopy a; h a; quncopy a d cannot form the required source pair after H changes a. Its literal late inverse also supplies the wrong reference: on initial a=d=0 it produces (|00>+|11>)/sqrt(2), so d is one with probability 1/2. The desired measurement-assisted realisation instead produces |+>_a|0>_d. The exact helpers in docs/notes/2026-11-02-contract-verification.md reproduce these states as flip(hadamard(flip({0:ONE},1,(0,)),0),1,(0,)) and hadamard(flip(flip({0:ONE},1,(0,)),1,(0,)),0), respectively. The mechanism needs to decide which source operation is being implemented and how its delayed cleanup remains selectable. *Fix:* In §§6.2 and 11 add: “A measure_fixup witness binds a well-formed source computing/cleanup pair at its original K65 carrier and an explicit later realised cleanup location. Source pairing uses the original legal source versions. The witness MAY delay that cleanup across identified intervening operations, extending workspace lifetimes and replacing the corresponding scheduling dependency edges. The checker verifies the complete realised region channel against the unchanged well-formed source region, including all interface wires, inherited controls, borrowed systems and clean workspace restoration. The current-version and window restrictions remain mandatory for reverse/recompute; the checked relocation rule governs measure_fixup.” Give this corrected example: reference source d=qcopy a; quncopy a d; h a; realised sequence d=qcopy a; h a; X-measure d; apply H_a Z_a^m H_a=X_a^m; reset/release d. Each branch operator on a is H/sqrt(2), and input zero finishes as |+>_a with d clean. For the AND example, use reference C; cx g y; C†; release g; h a, whose interface operation is H_a CCX(a,b;y); the delayed realisation uses H_a CZ(a,b)^m H_a. Alternatively, introduce an explicit transported logical-cleanup source operation with a defined unitary reference and amend source pairing and grammar accordingly. I would take the legal-source/checked-relocation approach because it preserves existing source bytes and hashes.
- **[sol] B2** (Recommended exact spec diff: §§12.1 and 12.3; bennett-4ht standing check; contract): The diff adds channel claims and certificate cleanup witnesses but never states their use in a mixed fat object containing native host code and only marked device modules. Hiding private outcomes from the launch measurement list does not establish certificate inventory or subject scope. The binding standing check explicitly requires this statement for certificate-layout changes; its absence requires revise. *Fix:* In §§12.1–12.3 add: “A mixed fat object may contain native host code and multiple embedded ISA modules. Each channel subject identifies a region closure within its embedded device object and covers that region’s declared device interface and device callee closure. Native host entry points, argv/envp and unlifted native library code are outside that quantum channel subject. The default certificate layout is one certificate per embedded ISA object, with a fat-object inventory mapping each device module to its object_hash and certificate. Native comparison, where claimed, concerns the materialised outlined region and its materialised callee closure. Private cleanup outcomes remain internal to the device invocation and do not enter the host-visible measurement inventory.” A unified certificate with explicit per-module bindings is also viable; I would take the per-module default because it preserves the existing single-object bindings.

## sol

The circuit, phase table and Kraus identities pass exact replay; the optional clean-isometry rule appears sound. The repair needs an explicit source-to-schedule relocation contract for closed-window cleanup and the mandatory mixed fat-object certificate statement. The §9 item 6 overstatement is nonblocking under R7.

**Path to accept:** 1. Add the explicit legal-source-to-delayed-realisation rule and corrected closed-window source/schedule example in B1. 2. Add the mixed fat-object channel scope and per-module certificate inventory statement in B2.

- **C1 4**: The proposed §6.4 confines measurement to private workspace, hides outcomes, requires reset and checks the complete data channel. Logical reversal with fresh outcomes is physically sound. *Change:* In §14.2 add: “A private measurement-assisted realisation denotes the channel ρ ↦ Σ_m K_mρK_m† on the declared interface; its workspace begins and ends clean, and private outcomes are discarded.”
- **C2 4**: Exact replay confirms the eight columns of C, its clean-input phase +1, and the stated dirty-target phases. The four-T compute, zero-T measurement cleanup and distinct controlled-adder costs agree with [Gidney’s paper](https://arxiv.org/pdf/1709.06648). Native CCX retains its arbitrary-target contract. *Change:* In §6.4 state: “The default private measurement primitive is computational-basis projective measurement. X-basis measurement expands as H followed by that primitive; reset applies X to each measured bit whose outcome is one. These events create no source-level CC measure frame.”
- **C3 3**: The transported correction and inherited-control checks are sound. However, the closed-window permission is not reconciled with §6.2’s current-version requirement and §11/K81’s source pairing before realisation selection. *Change:* In §§6.2 and 11 state: “measure_fixup may delay a well-formed source cleanup beyond its source window; its witness binds the original carrier and the realised cleanup location, and whole-region channel verification authorises the specified scheduling dependency changes.” Add the complete rule and example specified in B1.
- **C4 4**: The Boolean capability, mid-circuit measurement requirement, reset costs, feedforward latency and outcome-independent reserved charges provide the necessary resource obligations. *Change:* In §11 state: “Absent start entries, reserved cleanup slots execute sequentially in bound-expansion order. An outcome-dependent slot starts no earlier than measurement completion plus feedforward_latency. Every reservation remains charged for every outcome.”
- **C5 3**: Expansion versioning and consumer support are addressed. The catalog check reproduces 219 recipes and hash 5de4e4995350313e50217880ba1b95de39cd043283b726337d4894efb005d197. Certificate-only additions do not enter §9.2’s source identity envelopes. The required mixed fat-object certificate scope is absent. *Change:* In §12.3 add: “For a mixed fat object, the default is one device certificate per embedded ISA object, with an outer inventory associating each module with its object_hash and certificate.” Add the channel-scope statement specified in B2.
- **C6 4**: The reproduced exact script passes eight AND columns, 32 inverse columns, 128 corrected branch columns and three negative channels. Branch-operator equality establishes preservation of external correlations. The clean-isometry extension checks exact amplitudes and does not misuse T3. *Change:* In §15 add a source-and-schedule vector: “Source qcopy/quncopy/H and its delayed measurement realisation implement H with clean workspace; literal qcopy/H/quncopy fails, yielding workspace-one probability 1/2 on input zero.”
- **C7 3**: The proposal addresses the advisor-confirmed uncontrolled-cleanup gap and preserves unitary cleanup under control. Its §9 item 6 claim is overstated under R7. The certificate changes do not state how a mixed fat object uses them, failing bennett-4ht. *Change:* In §§12.1–12.3 state: “Quantum channel subjects cover the identified embedded ISA module and its device closure; native host code remains outside those subjects, with module certificates associated by the fat object’s inventory.”
- **C8 4**: The proposal separates source identity, implementation variants, private outcomes and resource accounting clearly. The principal implementation ambiguity is the relationship between legal source cleanup and a delayed realised cleanup. *Change:* In §11/K80 state: “Unless the new bound expansion explicitly specifies otherwise, measure_fixup replacement events use the original cleanup carrier’s coordinates and contiguous emitted ordinals; outcome selection never renumbers reserved slots.”

Defect statement: replace the §9 item 6 sentence with: “North Star §9 item 6 identifies the controlled form as open; §3.1 explicitly sanctions unitary cleanup under control until that form is fixed. The present blocking scope defect concerns the uncontrolled measurement capability.” This is the overstated premise identified by R7; the proposed diff preserves the fallback.

## codex

Revise. The circuit algebra, transported corrections, clean-isometry soundness, cost qualifications and unchanged-catalog claim check out. Two blockers remain: the closed-window mechanism lacks a defined relationship to legal unitary source cleanup, and the new channel/certificate contract lacks the required mixed-fat-object statement. The §9 item 6 overstatement is nonblocking under R7.

**Path to accept:** 1. Define the source-to-realization rule for delayed closed-window cleanup and publish the corrected source/realization vector in L2P-1. 2. Add the mixed-fat-object channel and certificate boundary in L2P-2. No broader provenance extension or mandatory measurement cleanup under control is needed.

- **C1 4**: The proposal distinguishes private cleanup outcomes from source measurements and requires a unitary-equivalent data channel with a separately checked logical inverse. These are sound machine-level obligations. *Change:* In §14.2 add: "Private cleanup outcomes belong to the implementation environment; after fixup and workspace reset, the induced channel on the complete live interface, including external correlations, is the operation checked under §6.4."
- **C2 4**: The exact verification script reproduces all eight columns of C, the clean-target compute/use/C† result, and the corrected measurement branches. C is correctly distinguished from arbitrary-target CCX. *Change:* In §6.4 state the default measurement construction: "X-basis cleanup applies H to each designated workspace wire, measures computationally, applies the outcome-indexed correction, and resets the measured workspace before release; basis-change and reset operations are explicit expansion events."
- **C3 3**: The clean-isometry provenance extension is sound under its exact, complete-column hypotheses. However, the closed-window exception does not reconcile source cleanup pairing and reference semantics with delayed physical cleanup. *Change:* In §§6.2/6.4/11 state: "Source cleanup pairing is established at the original legal source point; a checked measure_fixup realization may delay its physical cleanup, with actual operand versions and extended lifetimes recorded, while preserving the complete original source channel."
- **C4 4**: The proposal requires measurement capability, reset costs, feedforward latency, and outcome-independent padded charges. A separately versioned expansion document preserves deterministic accounting. *Change:* In §11 add: "An outcome-dependent correction starts no earlier than the end of its prerequisite measurement plus the target's feedforward_latency; reserved conditional slots retain their duration and resource charge on every outcome." For measurement ending at time 2 and latency 3, the correction starts at or after time 5.
- **C5 3**: Invocation-context binding and expansion migration are addressed. The catalog check reproduces 219 recipes and hash 5de4e4995350313e50217880ba1b95de39cd043283b726337d4894efb005d197. Unchanged 0.9 source envelopes can retain their hashes. The required mixed-fat-object certificate boundary is absent. *Change:* In §§12.1/12.3 add: "Cleanup claims and certificate inventories cover the selected VM closure and its device invocation contexts; a mixed fat object's native host binary and unmarked native callees are outside that quantum subject."
- **C6 4**: The exact-ring script passes, including 128 corrected branch columns and three negative channels. The proposed full-channel and inherited-control obligations are appropriate. The zero-error structural route would benefit from an explicit default distinct from §12.1's strictly positive SDP test. *Change:* In §12.1 add: "For an exact channel-identity claim, the default check compares Σm Km Eij Km† with V Eij V† exactly for every interface matrix unit Eij; this route does not require a strictly feasible numerical SDP witness."
- **C7 3**: The established uncontrolled-cleanup gap remains the correct motivation. The reported four-T construction, zero-T measurement cleanup, and separately costed controlled adder agree with [Gidney's paper](https://doi.org/10.22331/q-2018-06-18-74). R7 correctly qualifies the note's §9 item 6 claim. The mandatory mixed-fat-object check is not satisfied. *Change:* Add the mixed-object rule in blocker L2P-2, explicitly retaining native main, argv/envp, unmarked libc, and per-device-closure channel verification.
- **C8 3**: The proposal supplies useful circuits, negative vectors, resource obligations, and consumer migration. An implementer still needs a semantic decision identifying the legal unitary source and the permitted delayed realization for the closed-window example. *Change:* Replace the closed-window example with two explicitly distinguished traces: source C; CX(g,y); C†; release(g); H(a), and realization C; CX(g,y); H(a); X-measure(g); conditional H(a)CZ(a,b)H(a); reset/release(g), with reference operation H(a)CCX(a,b;y).
