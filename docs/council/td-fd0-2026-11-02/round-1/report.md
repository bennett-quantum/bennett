## sol

The cited 0.9 import gap is real, the worked arithmetic and fixture hashes reproduce, and the risk/error separation is sound. Revise five contract issues: operational rebinding, standalone identity, selector verdicts, catalog migration and mixed-fat-object coverage. The core remains acceptable; the 0.10 route can preserve current concrete estimate capabilities.

**Path to accept:** First freeze operational parameter dependencies against report/invoke rebinding. Then complete standalone report subjects with variant and inherited controls. Correct the missing-selector verdict, specify the ref-library migration for full-version 0.10, and add the mixed-fat-object statement and example. These changes suffice without implementing adapters, a general algebraic evaluator or proof machinery in this round.

- **C1 5**: The insertion preserves the machine state and step relation. Model-validation failures remain separate from ISA faults. *Change:* No change required. Retain §12.3's sentence: "No model output changes the object's instruction semantics."
- **C2 5**: No instruction, operand schema or source budget is changed. Operational destinations are explicitly enumerated. *Change:* No change required. Retain §8.5's prohibition on binding quantum operations, interface widths and source budgets.
- **C3 5**: Physical risk, approximation epsilon and oracle faults remain distinct. Positive modeled risk with exact logical epsilon zero is sound under those stated meanings. *Change:* No change required. Retain the vector requiring positive physical risk to leave logical epsilon and independently established oracle fault claims unchanged.
- **C4 3**: Units, exact arithmetic, intervals and shared reservations are substantially specified. However, report-level algorithm rebinding can contradict operational target bindings, and the missing-selector vector contradicts the objective rule. *Change:* In §8.5 state: "Every parameter transitively influencing an operational binding is operational regardless of its declared role and MUST retain its resolved target value in reports and invokes."
- **C5 3**: Scheduled context binding is explicit, but standalone report subjects omit variant and inherited controls. The full-version release route also leaves the reference-library migration unresolved. *Change:* In §8.5 define report subjects as "{closure_hash:H,variant:S,inherited_controls:N,invocation:Invocation,context?:ContextKey}" and require every component to match the invocation being described.
- **C6 4**: The read-only arithmetic replay passed; both fixture hashes reproduced. Exact algebraic evaluation and independent checking obligations are stated without claiming an implemented general checker. One acceptance vector prescribes the wrong verdict. *Change:* In Conformance vectors replace the final row with: "Explicit selector with bound dependencies: concrete scalar; explicit selector with free dependencies: unresolved symbolic objective; missing selector for a model-resource objective term: validation error."
- **C7 4**: The 0.9 defect is real, and concrete scalar instances retain a path to the demo estimates. The symbolic-count and format-version premises agree with [Qualtran's protocol](https://qualtran.readthedocs.io/en/latest/resource_counting/call_graph.html) and [release notes](https://github.com/quantumlib/Qualtran/releases). The required mixed-fat-object statement is absent. *Change:* Add to §12.3: "In a mixed fat object, each model report describes an identified embedded device object and marked region; native host code remains native and is not assumed to belong to that device object's closure."
- **C8 4**: The proposal provides usable schemas, examples and honest implementation limits. The catalog check reproduced 219 recipes and the stated hash; K82 reproduced 54 interfaces, 20 edges, 86 instances and 16 cases. Publication instructions nevertheless conflict with the inherited default expansion binding. *Change:* In Consumer impact state: "Normal full-version 0.10 publication republishes ref for ISA 0.10, recomputes its versioned catalog hash, and rebinds dependent schedules and certificates even when every recipe remains unchanged."

Consumer impact / companion 0.9 status entry: state, "Deferring imported-model interchange to 0.10 does not waive §10.1's existing obligation to produce padded estimates under named concrete targets for the demo ladder, including SQLite N=2^20. Fully bound scalar 0.9 targets remain the compatibility construction; symbolic interchange remains explicitly blocked by fd0/gyp pending the §8.5 mechanism." The route need not amend 0.9 schemas, and its current scalar path does not itself remove those concrete estimate capabilities.

Add a Unicode-key vector: U+10000 sorts before U+E000 under JCS, whereas Python's default key ordering reverses them. The reproduced fixture hash is correct; the helper is not a general canonicalizer. See [RFC 8785 §3.2.3](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.2.3).

- **C1 5**: The insertion changes target and certificate accounting, not §3 state or stepping. Validation failures are explicitly separated from executed-program faults. *Change:* No machine-model amendment needed.
