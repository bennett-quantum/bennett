- **[fable] BD2-1** (§10 TDL-2 (View), §18.3 `compute` row, §18.4; core/S0): §18.3: 'compute(f, use, budget, env): E_f = gen(f, env); the TDL-8 copies of E_f's fault registers; E_u = gen(use, env); then the events E_f, copies, E_u, adjoint(E_f)'. E_f is appended (or applied) only after gen(use) has run. TDL-2's view rule reads: 'a byte of object X has view Co if K(X) = Co, or if the generation's recorder (or a recorder of an enclosing generation of the same invocation) holds an event that writes it …; otherwise its view is Cl and its value is the shadow updated by the recorder's own classical events.' gen(f)'s recorder has been popped by the time gen(use) runs, is not gen(use)'s own recorder and is not enclosing, so under the literal text `use` sees neither f's classical writes (xmask events) nor its Co writes: `compute(f = {t = g(x)}, use = {if (t) …})` with t in `env` reads the stale t. The trace runtime (f, use, f in sequence) gives the other reading. Two readings, two results; the §18.8 examples (`set9`/`flip`, `copy`/`kick`) never let `use` read what `f` wrote, so no example decides it. *Fix:* TDL-2 'View', add after the view sentence: 'For `compute(f, use, …)`, the recorder of gen(f) is retained after gen(f) ends and counts, for gen(use) and for the construction of adjoint(E_f), as a recorder of the same invocation: a byte written by an event of E_f with a non-empty control set or a Co value has view Co in gen(use); a byte written only by classical events of E_f has view Cl with the value those events give it.' In §18.3 `compute`: 'E_u = gen(use, env) with E_f's recorder visible (TDL-2)'. Add to §18.8 a `tdl=`/`state=` witness: `f` stores 9 into a Cl global `@t`, `use` branches on `@t == 9` and flips `%t`; expected events: `xmask @t+0 0x09`, `x H1.0` (unconditional, since `use` sees 9), `xmask @t+0 0x09`.
- **[fable] BD2-2** (§10 TDL-11 (`__bennett_observe`), TDL-2 object states; core/S0): TDL-11: '`__bennett_observe(p, len)` … lowers to: … measure r, which collapses the arena cells identically; the outcome written to the shadow; an xmask of the outcome out of the arena cells, returning them to |0⟩; K := Cl for every object whose bytes are all observed.' With B equal to the common-prefix length plus three, W0 succeeds while W1 exhausts its budget. - **[codex] D02-02** (§10 TDL-2 and TDL-11; core/S0): K is defined per object, while observe may cover only part of an object. TDL-11 writes the measured bytes to the shadow and clears their arena cells, but sets K=Cl only when all object bytes are observed. For a two-byte Co object, observing its first byte with outcome 1 leaves K=Co and that arena byte zero. A subsequent slice reads zero from the supposedly authoritative arena instead of 1. *Fix:* State in TDL-2/TDL-11: 'K and shadow validity are maintained per byte interval. observe changes each observed interval to Cl after copying its outcome to the shadow and clearing its arena cells; unobserved intervals retain their previous state. Loads select the authoritative representation interval by interval.' Alternatively retain observed values in the arena and track separate classical-valid intervals; I prefer the first construction. The witness's subsequent read must return 1.
- **[codex] D02-03** (§10 TDL-2 view, TDL-3 branch conversion and TDL-5; core/S0): TDL-3 executes both arms of a Co branch during generation, while TDL-2 makes a byte's view Co once the recorder contains a predicated write. Starting with Cl x=0, 'if (w) x=5; else x=7' therefore makes the second generated arm see the first arm's write, although the arms are mutually exclusive. It can encounter TDL-5(d), or use the wrong old value when constructing its mask. No branch-local view rule resolves this. *Fix:* Add to TDL-3: 'Each arm is generated from a separate copy of the pre-branch view. Within an arm, its own classical updates are interpreted conditional on that arm being taken. Events retain their branch predicates; views merge only at the join.' For the witness, emit masks 0 xor 5 under w and 0 xor 7 under not-w. The resulting byte is 5 when w=1 and 7 when w=0, with no overwrite rejection.
- **[codex] D02-04** (§10 TDL-5(c), TDL-8 and TDL-10; core/S0): TDL-8 says a faulting slice's zero payload means its consumers leave the arena unchanged. This is false for exchange and negative predicates. In TDL-5(c), a fault produces t=0 and xchg overwrites a nonzero cell with zero. A failed condition slice similarly produces condition 0, enabling the else arm. Faults can therefore cause writes or gates that the stated fault semantics forbids. *Fix:* State: 'Every event consuming a fallible slice result is additionally controlled on that slice's code being zero; with multiple required results, all corresponding codes must be zero. Failure selects neither arm of a dependent branch. Cleanup retains the success predicates until their last use.' With an initial cell value 5 and a budget-zero value slice, the exchange must not occur, the cell remains 5 and the retained fault is 1.
- **[codex] D02-05** (§10 TDL-5(b), TDL-7; §18.4; Appendix A11; core/S0): TDL-7 turns uncleared condition/data registers into implicit outputs and measures them at the run epilogue. This can replace a promised action by a channel, and adj(f) allocates new history rather than receiving the forward invocation's history. For example, on a Co byte restricted to 0 and 1, 'if (x != 0) x ^= 1' passes the local library-bijection store rule, maps both visible values to zero and retains the distinguishing condition. Measuring that condition destroys coherence. This also conflicts with the ratified E3 decision against implicit history semantics. *Fix:* State: 'The complete predicated update, including its condition, must be a total bijection on the declared mutable interface. Non-fault workspace must be cleaned before return; compiler-retained garbage is not implicitly measured.' The witness must use an out-of-place oracle or compute/use/uncompute, or fail the existing coherent-overwrite rule. A second viable design is explicit caller-owned history passed to both forward and adjoint invocations, but that requires the opt-in interface and north-star amendment described by E3; I would retain E3's current clean-workspace default.
- **[codex] D02-06** (§7.5(a) deferred measurement; core/S0): The rule replaces measurement with qcopy and then quncopy whenever its window remains open. That erases a measurement instead of deferring its channel. Prepare q in |+>, invoke a deferred-measurement region whose measurement result is unused, then apply H and measure q. The draft gives 0 with certainty; preserving the original measurement gives 0 and 1 with probability 1/2. *Fix:* Replace the cleanup sentence with: 'A deferred measurement retains its coherent outcome record until a permitted measurement boundary, where that record is measured; it may be removed earlier only when the complete resulting instrument is unchanged. An open uncomputation window alone does not justify removal.' The witness must produce probabilities 1/2 and 1/2. Treat these intentional measurement records separately from incidental workspace governed by TDL-7.
- **[codex] D02-07** (§10 TDL-12; §11.1; Appendix A10; core/S0): Every effect in an action is assigned fault 8 because actions have no device descriptor. The north star promises closed virtualised device state under coherent control, and the ratified outline provided that mechanism. A controlled console operation that has a reversible console model is not intrinsically unvirtualisable. The missing binding facility is a dialect omission, not an ISA limitation. *Fix:* Add an action device-binding mechanism, preferably inherited per-run bindings, and state: 'Bound console, clock, entropy and block operations become controlled reversible transitions of declared virtual device state; their external effects remain deferred until observation. Code 8 applies only to unmodelled or unbound operations.' Update tdl-effect with a bound virtual console: the control-1 branch appends bytes 0x21,0x0a, the control-0 branch preserves the buffer, and the fault rate is zero. An explicit action descriptor is an alternative; I prefer inheritance to preserve existing marker signatures.
- **[codex] D02-08** (§9.3; §10 TDL-3/TDL-9; §18.4; core/S0): Only Co slices and Co-trip-count loops receive bounds. G executes ordinary classical code during gen without a budget rule. A materialised action body containing an infinite classical loop and no Co values never finishes generation, even under a finite region budget and even when its external control is zero. This fails the promised bounded coherent execution mechanism. *Fix:* Add a bounded G execution rule: 'Generation receives its own full region budget. It charges one step before each materialised LLVM instruction other than phi/debug/mark instructions, and enforces heap and depth limits before mutation. Exhaustion stops generation and emits the corresponding fault-oracle event under the invocation/path controls; no further source instruction executes.' Preserve the separate full budget for each slice. A marker-free infinite loop must produce a finite event list and a controlled code-1 outcome, not hang compilation or execution.
- **[codex] D02-09** (§8.5 entry-state transfer; §5; §17.3; core/S0): §8.5 promises a private copy of the caller's whole memory, but its snapshot contains mutable globals and heap bytes only when R contains a heap object. §5 classifies allocas separately, and that analysis precedes N24. A CC caller that stores 7 in an alloca and passes its address as an ARG to an oracle load can therefore transfer neither the alloca bytes nor their shadow-stack backing bytes; replay supplies zero rather than 7. *Fix:* State in §8.5: 'After normalisation, translate every source read-set object to its runtime backing allocation. If an oracle may read any caller alloca or shadow-stack frame, snapshot the corresponding live backing storage and allocation metadata, including its current bytes and addresses.' A sound default is to copy all live caller heap and shadow-stack backing allocations when such reachability is uncertain. The example must return payload 7 and preserve the caller's byte.
- **[codex] D02-10** (§8.5 release; §10 TDL-11 observe; core/S0): The snapshot is released by measure of a potentially enormous concatenated qreg; observe likewise measures a fresh register of 8·len wires. ISA §3.3 permits measure only for qreg[n] with n≤128, and a qreg.slice view cannot be measured. These are illegal default constructions for ordinary snapshots and observations longer than sixteen bytes. *Fix:* For §8.5 state: 'Retain the classical snapshot bytes for the register's lifetime. Release it by slicing at most 128 bits at a time, invoking the same xor128 preparation oracle with those original bytes, then qreg.free the now-clean whole register.' For TDL-11 state: 'Copy and measure successive chunks of at most sixteen bytes into fresh non-view registers; update the corresponding coherence intervals after each chunk.' Sequential computational-basis chunk measurements must preserve the joint outcome distribution.
- **[codex] D02-11** (§5.2 PT2 and PT6; core/S0): Two rules under-approximate reachable callees. PT6 seeds initialiser atoms only for constant globals, so an ordinary mutable '@cb = global ptr @f' can load an empty candidate set. PT2 bounds a nonconstant GEP index by the syntactic array dimension, but LLVM permits indexing beyond that dimension within the actual allocation. A [2 x ptr] allocation accessed through 'getelementptr [1 x ptr], ..., 0, i' at i=1 can legally select its second function, which PT2 omits. LLVM explicitly documents this distinction. [LLVM GEP rules](https://llvm.org/docs/GetElementPtr.html) *Fix:* State: 'Seed initial contents of every global, mutable or constant, before the points-to fixpoint; stores union additional contents. GEP array dimensions determine stride, not an index bound. Restrict offsets only using a sound index-value bound; otherwise cover the underlying object's possible offsets.' The mutable @cb case must include f. The two-entry table must include its second function for i=1, without taking the unmatched-call fault.
- **[codex] D02-12** (§12.6 vector scalarisation; core/S0): The load/store rule uses 'getelementptr T, p, k' for every lane. Sub-byte vector lanes are packed, whereas scalar i1 memory accesses occupy bytes. Loading <8 x i1> from one byte 0x80 and extracting lane 7 must return 1; the draft instead accesses byte p+7, potentially faulting. An LLVM 18 constant-folding probe confirms the expected result. [LLVM vector layout](https://www.llvm.org/docs/LangRef.html) *Fix:* Add: 'Vector memory scalarisation preserves the vector's packed bit layout. For <L x iM> with sub-byte lanes, load the packed byte range, extract lane k from bits [kM,(k+1)M), and pack stores into the same range; do not use scalar allocation stride.' The <8 x i1> witness reads exactly one byte and returns 1 with no memory fault.
- **[codex] D02-13** (§12.7 wide integers; core/S0): The top limb is declared i(N−64(L−1)), but addition always extends carry to i64 and sext always uses 'ashr a_top, 63'. - **[codex] D02-16** (§12.2 N4; §14.4–§14.7; core/S0): The unwind transforms make __cxa_throw and related nonlocal-transfer functions set a flag and return, but N4 does not remove noreturn. - **[codex] D02-17** (§12.8 GC intrinsic row; core/S0): The rule 'gc.get.pointer.base(p) → p; gc.get.pointer.offset(p) → 0' is false for derived pointers. - **[codex] D02-18** (§8.7 verification and T-BUDGET; core/S0): The text takes B_min over a sample and then concludes that the pair is valid for exactly B≥B_min.
