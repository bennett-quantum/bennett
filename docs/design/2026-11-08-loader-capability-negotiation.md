## Summary

K91's `token_aliases/1` negotiation remains undefined: §10.1 and the K91 row acknowledge that defect (b-isa-spec-b3ui).
Recommend **A: independent launch/sched feature-query manifests**, with an explicit schema version and fail-before-request compatibility handling.
Support must cover the role's additive entry point **and** identity/metadata semantics; exported symbols or an object header saying 0.9 cannot establish it.
Keep every consistent partition admissible; absence means a deployment capability gap, never permission to erase aliases, substitute a bound, or reject the source program.
The VM currently exposes an alias-aware estimate that reaches an unavailable-estimate error, and its legacy estimate still has 0.8 arity; the driver/runtimes do not implement a negotiation path.
This is a maintainer decision note with three alternatives, proposed text and follow-up beads; it publishes no contract and changes no implementation.

## Rules shared by all three alternatives

**Compatibility.** Here old/new means before/after negotiation within published launch/sched 0.9; a 0.8 binary requires a separately selected provider with its matching ABI. A single unversioned C address cannot implement both estimate signatures. Old caller/new library: keep each previously published layout callable under its actual ABI family; under launch/sched 0.9 retain token-free inference `[0]` for oracles and `[]` for actions, and `BENNETT_E_ARG` for tuple-only token-argument requests lacking aliases. Live-handle execution still derives actual identities. No tuple interning, fresh-mint reuse or serialized host ids (Q06–Q09, Q18–Q20).

**New caller/old library:** resolve new entry points optionally on the selected provider before invoking them; a static link missing required symbols fails explicitly. Missing entry points/support, unsupported protocol versions, or inconsistent advertisements produce a loader compatibility diagnostic corresponding to `BENNETT_E_VERSION`, before an alias-aware call/effect. An absent symbol cannot return a C status: the loader synthesizes that diagnostic. Never retry the request after deleting its partition. A token-free legacy path is allowed only when its base ABI is independently known, not inferred from symbol names or the ISA header.

**Meaning of support.** Negotiate every participating provider/role independently; launch support never certifies a separately loaded scheduler, checker or certificate reader. The launch role's pledge covers its additive estimator plus §5.4/§7.4/§12.3 identity and metadata rules; the sched role covers its setter, scheduler and produced metadata. Together these cover both additive symbols without requiring both in every shared library. Checkers/readers must independently implement the same bindings before consuming those artifacts.

**No narrowing.** An unavailable library is a deployment incompatibility, not an illegal partition/program or a completed implementation. Preserve the unresolved request and require a conforming provider; do not claim a successful estimate, a cross-partition bound as exact, or source rejection. Capability support does not promise feasibility for every target; ordinary specified request/target errors remain distinct (Q13–Q15).

All alternatives first make this shared editorial cleanup, then insert the selected contract. Keep the interim warning until the chosen text and vectors have been accepted; revise K91's row to name that mechanism only on publication. No edit is applied by this note.

## A. Feature-query manifests — recommended

**Exact proposal.** Two side-effect-free exports, one per role; library-owned immutable UTF-8/JCS bytes live until that provider is unloaded. The caller owns neither buffer and passes no program/request handle. On success length excludes a NUL; null output pointers are `BENNETT_E_ARG`; with valid outputs any error sets NULL/0. No allocation/run/target selection occurs. The schema version is the exact string `bennett.abi-features/1`; `abi` names the C ABI family, separately from object versions.
