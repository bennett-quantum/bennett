# Function pointers inside lifted oracles

Design disposition for **bennett-0vi / plan R2**, 2026-11-08. Design only: no implementation or rung-4 pass is claimed.

## 1. Promise, evidence and verdict

**Confirmed: function-pointer calls need no new ISA instruction.** ISA 0.9 §4.2 says “control never leaves a function except through `lift.call`/`lift.ret`” and gives the call form `w = lift.call @f (a_1..a_m) (tokens..) (classical..) (mem..)`. Thus `qjumpr` is intra-function and the callee symbol is static; neither fact prevents comparing a pointer value and branching to a static call. The rows needed for that construction already exist.[^isa-rows] This confirms expressibility, not successful compilation, affordable execution, or a certificate for SQLite.

The promise is the complete North Star §8 rung 4:

> SQLite compiled unmodified to the coherent tier under a region budget, with an in-memory VFS over quantum-addressed memory. Database of N rows fixed classically before entry; the predicate is a real SQL query parameterised by a `rowid` bound from the superposed register; the oracle bit is the query's match for that row. (a) Oracle verified by §5.1 part 1 over all rows and all target values for N ≤ 2¹⁰, fault rate zero. (b) End-to-end Grover by state-vector simulation with branch enumeration at N ≤ 2⁸. (c) A resource estimate for N = 2²⁰ under a named target, reporting the budget and the padded cost. Nobody rewrote SQLite.

Source: [North Star §8](../Bennett-NorthStar.md#8-demo-ladder-success-criteria-each-with-its-acceptance-test). Its §3.1 also requires “No per-loop source annotation is ever required”. Real VFS, allocator and SQL callback calls must therefore work; source rewriting, direct-call-only substitutes and disabling vectorisation are not acceptance strategies.

Evidence read: `bd show bennett-0vi`; dialect `b-dialect-spec-8wf.35` (O-01), `.22` (B-16), `.23` (B-22), `.30` (B-33); plugin `bp-fj1`, `bp-1bb`, each from its main checkout. ## 2. What the contracts establish

**Calls and jumps.** ISA 0.9 §3.7 says “Resolve the fixed callee instance above”; §4.2's `qjumpr` row faults when `(a < first_f) ∨ (a ≥ first_f + n_f)`. Use `lift.call` for cross-function calls and normal return/history handling. ISA 0.8 §4.2 already has `w = lift.call @f (a_1..a_m)` and the restriction “control never leaves a function except through” its call/return mechanism. Its row describes function **blocks**; 0.9 describes function-instance **rows**. This difference must not become a function-address encoding.[^isa-08]

**Constants and images.** ISA 0.9 §4.2 provides `w = lift.const.iN c`; §9.1 says “`data` lines are `NAME SP HEX`”; §7.2 fixes “each global's base and image”. These supply ordinary integer bits and stored bytes, not a native-code execution address space. Dialect §4.4 supplies their meaning: “A(F) is the value of `ptr @F` in every tier”, including “in every data image: global initialisers, vtables, function tables”.[^addresses] A(F), an ISA dispatch-row index, and the symbol `@L(F)` are three distinct things.

**Version boundary.** Published dialect 0.2.14 targets ISA 0.8; the 0.3 draft §1.7 explicitly limits its accepted `0.3-r1` profile: “All other clauses, and the coherent/quantum parts of these sections, remain **ungraded**.” The same paragraph says they “remain specified and binding wherever applicable”. This note establishes that ISA 0.9 can express the design; it does not promote the full coherent 0.3 track to accepted status.[^versions] Rung-4 publication and pin choices remain question 1 below.

**E3 is absent deliberately.** ISA 0.9 §0.3 places SQLite E1–E5 under “Considered and deferred” and “no 0.9 text”, retaining “compare tree plus static `lift.call`”. Calling E3 an implemented 0.9 row would be false.[^e3]

## 3. Candidate construction and convergence

Use one symbolic analysis solution for closure, arguments, returns, memory, tiers and dispatch. Dialect §4.1 S2 specifies “one fixpoint for points-to, value sets, region candidates”, explicitly including indirect-call candidates; §5.2 calls it “the least fixpoint”.[^analysis]

1. **Seed function addresses in data.** Recursively traverse initialisers, including mutable globals, nested aggregates, aliases and constant-expression references. Keep function identities as `FN(F)` with storage intervals and representation widths; do not guess numeric A(F) before the comparison link. Continue propagation through copies, stores, loads and callback registration in heap objects. Dialect §5.2 requires “seed the initialiser atoms of every global, mutable or constant” and says function addresses are “symbolic `FN` atoms during the analysis”.[^analysis]
2. **Compute each site's candidates.** Include the explicit FN alternatives. For top/unknown pointer alternatives include every address-used function anywhere in the linked program whose LLVM function type equals the call's. Do not prefilter to the already discovered direct closure, or infer C signatures from opaque `ptr` alone. Null, integers and unrecognised values do not justify an empty set when top remains. This is the published §14.2 rule, not unrestricted devirtualisation.[^dialect-candidates]
3. **Grow the closure together with memory flow.** Bind actual arguments and returned values for every candidate, then repeat. A callback can expose another store, function address or candidate. Retain handle ROOT alternatives when handles cross callbacks; the B-22 history does not justify a blanket address-taken rejection. PT9 expressly covers “direct call of G, or indirect call with candidate G”.[^analysis]
4. **Freeze only at convergence.** Preserve source address keys separately from resolved bodies. Analyse the normalisation's value effects before freezing domains; numeric A(F) arrives after S7 and before S8.[^analysis] Record a deterministic per-site manifest: source point, type, FN/top provenance, source keys, resolved variants, declarations, and candidate count. This manifest is proposed evidence, not a new ISA metadata field.

## 4. Encoding and dispatch lowering

**One address map.** Resolve A(F) from the driver's deterministic comparison link. Apply exactly those bits to function constants, global initialisers (`aBuiltinFunc`, VFS/io/pcache tables), copied tables and pointer comparisons/`ptrtoint`. Preserve original host functions and shared globals; map A(F) to the device variant for the caller's tier/coherence signature. Dialect §4.3 says “Clones share every global: data is never cloned”; §4.4 requires a “common comparison-link function address”.[^addresses] A dense private function number or clone address would violate this contract even if calls appeared to work.

Scan symbol-bearing initialisers rather than treating arbitrary pointer-sized integers as relocations. After layout resolution, emit the relocated bytes using DataLayout's storage size, byte order and padding, then put them in ordinary ISA data images. Check code-constant bits, image bytes and dispatch keys against the same map. Runtime stores/copies must preserve those values too. The function-address bits are dispatch data; do not allocate executable text in lifted memory or bounds-check a call target as a data load. Memory used to **load** the pointer still needs its ordinary memory checks.[^addresses][^isa-images]

There is existing machinery to extend and test: `bennett-plugin/src/Production.cpp:585–604` uses `comparisonFunctionAddress(*fn)` and fails when a supplied comparison layout lacks a function; its no-layout path is explicitly labelled “Standalone comparison link”. `:309–311` emits CC constants plus `inttoptr`; `:1772–1790` recursively discovers relocation targets. The production oracle path calls `lowerScalar(...)` at `:945–953`. Lifted constants use comparison addresses at `bennett-plugin/src/Scalar.cpp:146–151`; images recursively encode aggregates and function relocations at `:685–708`. Production acceptance must supply the real comparison map; the standalone convention is not evidence of native equality.

**Compare-and-branch chain, then canonical tree.** A simple constructive lowering is an equality chain: materialise A(F₁), compare pointer, branch to `lift.call @L(F₁)` or the next test; repeat; each call leaf jumps to a shared continuation; the default executes `fault 4`. This proves ISA expressibility. For canonical reference objects follow dialect §16.4's hybrid tree, not a newly chosen chain: up to three sorted keys use equality chains; larger sets split with unsigned less-than. The indirect-call row requires “then `qjump` to the continuation, default `fault 4`”.[^dispatch]

That mapping already appears at `bennett-plugin/src/Scalar.cpp:305–348`: `if(hi-lo+1<=3)`, `lift.icmp.eq`, `lift.icmp.ult`, static `lift.call`, and default `fault 4`. CC/R production uses a separate equality-first balanced emitter at `bennett-plugin/src/Production.cpp:610–624`, `:1386–1410`; it is not evidence of lifted row counts. Closure collection includes indirect candidates at `bennett-plugin/src/Scalar.cpp:784–802`, and `:997–1015` performs a fresh `Analysis analysis(m, &f); analysis.run();` after preparation. Optimising repeated analyses must preserve each materialised module's solution rather than reusing stale candidates.

**Cost, derived from the rows.** Count forward reference rows after pointer/argument preparation; exclude callee body/return, argument flattening and result unpacking. Every row is one step, including each `lift.const`.[^isa-rows] For a simple chain, a hit at position j costs `3j + 2` (constant, equality, branch per test; call and continuation jump); a miss costs `3k + 1`. This is a construction bound, not the published reference mapping.

For the canonical tree, let C(k) be the maximum number of comparison nodes visited: C(1..3)=k; for k>3, let l=⌊(k−1)/2⌋ and C(k)=1+max(C(l), C(k−l)). Each node is three rows. A worst successful hit costs `3C(k)+2`; a miss costs `3C(k)+1`. At **99 candidates**, C(99)=9: at most **29 rows** for a successful dispatch and **28** for a miss, with the stated exclusions. A chain would cost 299 at its last hit. Static dispatch size remains O(k), plus one compiled body per distinct reachable variant; dynamic canonical dispatch is O(log k). At zero candidates the canonical mapping executes `qjump` to the default plus `fault 4`: two rows. B=0 or an earlier budget cut still yields the earlier step-budget outcome, not an unconditional trap.[^dispatch][^isa-oracle]

The spike §5.2(ii) says “Cost about 2⌈log₂k⌉+1 rows per call”; that is not an exact budget formula for these constant-materialising rows or this hybrid tree. Its reported 532 dynamic indirect calls and approximate 324k-row index space are historical estimates. Recompute actual reference-body costs and padded resources; do not multiply those estimates into a certificate. ISA §3.6 includes every transitive `lift.call` dependency in the index space, so candidate breadth affects static layout and realisation cost as well as per-call steps.[^isa-index]

**Failure is a reversible outcome.** A trap at an indirect site means lifted `fault 4` (`FAULT_UB_TRAP`), never a host abort, measurement, deleted call, zero-return stub, or classical `trap` inside the oracle. ISA §5.1 forbids classical `trap` in a region; §4.2 makes `fault` a HALT successor.[^isa-rows] If reached within budget, the result is `(0,4)`: target unchanged, fault register XORed by 4, input/image/dirty state restored by prefix reversal, including all pointer comparisons and call history. This follows ISA §5.2's construction, not an assumption that faults are irreversible.[^isa-oracle]

The 73 empty sites may be dormant; the inventory does not prove that on the rung's domain. Never discard defined native successes to obtain a smaller domain. Require all declared rung inputs to avoid these sites (or correct the candidate analysis if a valid target was missed), with zero fault rate. Include no-match/empty/declaration cases in separate full-tuple fault fixtures. Certificates must bind the relocated images and dispatch closure, budget and tested domain; a structural dispatch argument alone does not prove the SQL predicate. ISA §12.1 requires exhaustive claims to “re-execute every domain element” and “compare full tuples”; sampled claims are “always **evidence**”.[^certificate]

**Optional E3.** The spike proposes `lift.callr a [@f…]`; published ISA 0.9 defers it.[^e3] A future proposal could package bounded address selection, no-match fault and static candidate dependencies into one mixed call row. It would need exact address-to-symbol bindings, signature checks, reversible selector/history capture, recursion/stack/depth behaviour, closure hashing, reference semantics, executor support and conformance vectors. Making it one reference step also changes finite-budget outcomes and demands a new versioned mapping. It may reduce dispatch rows, but selection gates and candidate bodies still cost resources. Rung 4 needs the present construction and measured costs; E3 is optional unless new acceptance evidence establishes a cost problem requiring a separately approved contract change. Executor optimisation under ISA §5.7 must retain the reference F_B, including its faults.[^transform]

## 6. Risks and numbered maintainer questions

1. **Coherent ISA 0.9 publication.** Which reviewed full dialect version or coherent profile will rung 4 pin? Recommend explicit coherent-profile acceptance and producer/executor pin migration; do not advertise `0.3-r1`'s R acceptance as L acceptance.[^versions]
2. **Source identities and ABI coverage.** Does acceptance require source-alias/forwarder addresses, cast/varargs callbacks and tier variants in the first fixture batch? Recommend yes: retain all source address keys and separately resolve bodies; exact function-type fallback alone is not a proof for every materialised ABI shape. Region §7.2 explicitly requires “retain A(S) for every original source function or alias”; cover this when identities meet ordinary callbacks too.[^dialect-candidates] Resolve any discovered conflicting rule before changing a contract.
3. **Empty-site evidence.** What reproducible evidence will establish that the actual module's zero-candidate/default sites are unreachable on the full rung domain? Recommend independent expected outputs plus exhaustive small-domain execution, per-site fault coverage and candidate manifests. The spike's 73 count is not such evidence; supported executions must not acquire a compiler-induced trap.
4. **Cost and E3 trigger.** Which regenerated reference budgets and named-target resource vector should replace the spike approximations? Recommend the canonical-row counts and measured pipeline receipts first; consider E3 only against that evidence, preserving reference-budget semantics or versioning the changed mapping.[^dispatch][^transform]

Primary risks are under-approximated data-derived targets, numerically different pointer encodings, analysis blow-up, stale candidates after normalisation, and incorrect finite-budget/fault cleanup. Candidate growth beyond the spike's 99 is supported work, not an invalid program. Questions and cross-repo follow-ups are queued in the job scratch directory for the orchestrator to file; no sibling beads were mutated.

## 7. Acceptance evidence and verification boundary

Acceptance needs a pinned compiler/dialect/ISA/runtime/executor matrix and the recorded comparison link, source hashes, flags, exact argv and candidate manifests. Exercise a genuinely indirect call loaded from each representative table family, including a superposed selector, and compare complete native/reference/VM tuples. Reproduce the empty/no-match and declaration fault cases, dispatch budget boundaries, recursive call reversal, image restoration, arbitrary initial targets/faults, dirty restoration, controlled invocation and adjoint composition. The full interface, not output-only equality or ancilla-zero alone, is the contract.[^isa-oracle][^certificate]

For rung 4(a), retain exhaustive all-row/all-target evidence through N≤2¹⁰, plus the full fault/dirty obligations of North Star §5.1: “every input x, every output-target value t, every fault-register value e, every value of every borrowed dirty ancilla d”. (b) must run end-to-end Grover with branch enumeration through N≤2⁸. (c) must report N=2²⁰, named target, budgets and padded resources. These are the §8 promise quoted above; do not replace them with sampled rows or a hand-written predicate.

This job verifies documentary claims only: quotations against the source files, code citations against the recorded snapshot, inventory arithmetic, dispatch-cost recurrence and Markdown/diff hygiene. It runs no compilation, simulator, conformance gate or sibling test suite. Thus R2's **ISA expressibility** is confirmed; bp-fj1, bp-1bb, coherent-version disposition and full rung-4 evidence remain open.
